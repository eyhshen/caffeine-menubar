# caffeine-menubar

macOS menu-bar keep-awake app (Python + rumps). One file of logic: `app.py`.
The cup icon steams whenever ANY `caffeinate` process is running; clicking it
toggles keep-awake globally. See `README.md` for user-facing docs — it is accurate.

## Run / test

```bash
./install.sh                 # venv + icons + LaunchAgent (starts now + at login)
.venv/bin/python app.py      # run once without installing
```

## The thing that will bite you

A live instance normally runs from THIS directory via LaunchAgent
`com.elaine.caffeine-menubar` (plist in `~/Library/LaunchAgents/`, written by
`install.sh`). After editing `app.py`, restart it:

```bash
launchctl kickstart -k "gui/$(id -u)/com.elaine.caffeine-menubar"
# or just rerun ./install.sh — it boots the agent out and back in
```

Running `python app.py` while the agent is up gives you two cups in the menu bar.
Runtime log: `~/Library/Logs/caffeine-menubar.log`.

## Boundaries

- `icons/*.png` are tracked but GENERATED by `make_icons.py` — edit the script
  and re-render, don't hand-edit the PNGs.
- `Caffeine.app/`, `.venv/`, `__pycache__/` are gitignored local artifacts.
- Clicking the cup off kills EVERY `caffeinate` on the machine by design
  (`pkill -x caffeinate`) — that's the feature, not a bug.
